# AGENTS.md — `hivemind-flask-chatroom`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

A multi-user Flask chatroom that connects to a HiveMind hub as a single
satellite and fans it out to many browser users: each visitor chats under
their own username, language, and site_id, messages are routed to the
assistant through the hub, and spoken replies stream back into the room. Part
of the [HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol
for connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core); this app
authenticates server-side via the
[hivemind-bus-client](https://github.com/JarbasHiveMind/hivemind-websocket-client)
Python library — browsers never see HiveMind credentials, they just pick a
name. The counterpart that connects client-side from each browser instead is
[HiveMind-webchat](https://github.com/JarbasHiveMind/HiveMind-webchat).

## Layout / build / test

- Package module: `hivemind_chatroom/`. Tests live in `tests/` (unit smoke in
  `tests/test_smoke.py`, real-hub e2e in `tests/e2e/`) — do not create a second
  test directory.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[e2e]" --prerelease=allow`
- Run the suite in the foreground: `pytest tests/ -q` (everything),
  `pytest tests/test_smoke.py -q` (unit only, no network — bus is stubbed),
  `pytest tests/e2e/ -q` (real `hivemind-core` master + real
  `HiveMessageBusClient` over hivescope's loopback WebSocket transport). The
  `[e2e]` extra installs the full HiveMind 2.x stack, so no test is ever
  skipped for a missing optional dependency.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is
  a bug to FIX at the source, not to work around with a pin downgrade.
- `pyproject.toml` is the single source of truth — no `setup.py`,
  `requirements.txt`, or `MANIFEST.in`. Version is dynamic from
  `hivemind_chatroom/version.py`; never hand-edit it, the shared release
  workflow bumps it from conventional-commit prefixes.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- This is a satellite app, not a client library or transport: it holds ONE set
  of HiveMind credentials (read from `~/.config/hivemind/_identity.json` via
  `HiveMessageBusClient(...).connect()`) and fans that single connection out to
  many browser users, each identified only by username/site_id/lang carried in
  the OVOS `Session`. Never make the Flask app accept or store per-browser
  HiveMind credentials — that is what HiveMind-webchat is for.
- Named chatroom sessions (`/chatroom/<username>/<site_id>/<lang>`) imply a
  remote client per the standing session-per-message rule: `Session` state is
  looked up per username on every message (`MessageHandler.sessions[user]`),
  never assumed to persist implicitly across requests.
- Bad or missing HiveMind credentials must fail fast at startup, not retry
  silently or hang — verify with `hivemind-client test-identity` before
  reporting a connection issue as a chatroom bug.
- Never hardcode secrets, hub host/port, or access keys in source, templates,
  or tests; they come from the identity file or, in `tests/e2e`, from the
  in-process hivescope harness.
- The README quickstart (`hivemind-core add-client` → `hivemind-client
  set-identity` → `hivemind-flask-chatroom --port 8985`) must stay runnable
  verbatim; if a change to identity handling or CLI flags breaks a step, fix
  the README in the same PR.
- `tests/e2e/test_acl.py` and `tests/e2e/test_bridge1_conformance.py` are
  shared conformance suites (ACL policy-admission, OVOS-BRIDGE-1/SESSION) —
  do not weaken or delete their assertions to make a change pass; a failure
  there means this satellite diverged from the shared spec, not that the test
  is wrong.
